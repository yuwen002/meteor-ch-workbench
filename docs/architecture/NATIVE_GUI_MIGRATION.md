# 原生 GUI 全量重构说明

## 2026-11-24 架构决策（优先级高于本文历史迁移记录）

用户已明确要求彻底切换到 Gio 原生桌面架构：不保留 Wails 兼容入口，也不把旧 Go 应用门面 / 业务实现作为最终后端。后续按新架构重新实现应用用例、连接管理、配置读写、查询编排、元数据、导入导出和工作区状态；旧实现仅可作为行为参考，不能因复用旧代码而计入迁移完成度。

本轮已删除根目录 Wails 启动入口 `main.go`、旧前端绑定门面 `app.go`、对应平台行为测试、`internal/platform/wailsadapter` 和 `wails.json`，并从 `go.mod` 移除 Wails v3 直接依赖。Gio 唯一桌面启动入口为 `cmd/meteor-ch-gio`。旧 `frontend/` 目录暂作为功能盘点与交互参考资料，不参与新应用启动和发布；待 Gio 功能逐项替代并完成验收后再整体删除。

`cmd/meteor-ch-gio` 当前已通过 `internal/bootstrap.NewDefault` 装配新架构，并由 `internal/gui/gioapp/app` 作为实际运行中的 Gio 界面。旧 `internal/gui/gioapp/window.go` 仍引用 `internal/app.Service`、`internal/config` 和 `internal/clickhouse`，但不属于新入口的运行链路；这些旧包和旧窗口代码暂留作功能迁移参考。后续必须逐项迁移并验收历史、收藏、设置、导入导出和结果导出等能力，再删除旧实现。ClickHouse 官方驱动及必要底层协议库属于基础设施依赖，不属于需要删除的旧业务逻辑。

## 目标与约束

本次工作从 Wails + Vue 切换为 Gio 原生 GUI，并进一步将旧 Go 应用门面和业务编排替换为清晰的新领域 / 应用服务。保留 ClickHouse 驱动与必要的本地数据兼容能力；不保留旧 GUI 入口和旧业务实现作为运行时兼容层。

- Community 核心采用 MIT 许可证。
- Pro 功能未来通过独立私有仓库和独立构建入口组合，不进入 Community 默认依赖。
- 不使用 Go `plugin` 作为跨平台扩展机制。
- 不以未经实测的框架宣传数据作为启动速度、内存或安装包体积结论。

## 目标分层（当前实际结构）

```text
cmd/meteor-ch-gio
  ├─ internal/bootstrap
  │    ├─ internal/application
  │    ├─ internal/domain
  │    ├─ internal/infrastructure
  │    └─ internal/platform
  └─ internal/gui/gioapp/app
       ├─ internal/gui/gioapp/connection
       └─ internal/gui/gioapp/workspace
```

依赖方向为 GUI → bootstrap / application → domain 与端口 ← infrastructure。旧 `internal/app` / `internal/config` / `internal/clickhouse` 不应再成为新功能的依赖。

## 历史迁移记录（下列早期批次描述仅用于追溯，不代表当前运行时依赖）

### 第一批：数据库与查询用例

新增 `internal/app.Service`，由应用入口注入配置管理、查询历史、标签页、收藏 SQL、ClickHouse 服务和用户设置依赖。已将以下业务流程从根目录 Wails App 方法委托到该服务：

- 连接保存、删除、测试和断开。
- SQL 查询、查询取消和查询历史记录。
- DDL/DML 单条执行与批量执行。
- 数据库、表、视图、表结构和集群元数据读取。

### 第二批：本地配置与工作区用例

已将以下用例纳入 `internal/app.Service`：

- 连接、文件夹列表及排序；配置导入、导出和格式元信息。
- 查询历史读取、删除和清空；收藏 SQL 增删改查。
- 标签页快照读写；用户设置读取与保存。
- 查询结果导出格式查询，以及向调用方提供的 `io.Writer` 写出结果。

新建连接时应用服务先生成 ID，再持久化并失效对应连接池，避免配置管理器内部生成 ID 后调用方仍持有空 ID 的问题。

默认依赖装配已抽取为 `internal/app.NewDefaultService`，统一创建本地配置管理器、查询历史、标签页、收藏 SQL、用户设置和 ClickHouse 服务；历史版本曾由 Wails 与 Gio 入口共用该构造函数；该兼容策略已于 2026-11-24 废弃，旧 Wails 门面和启动入口已删除。`internal/app.Service` 当前仅为 Gio 的过渡依赖，后续将按新领域边界重写。文件对话框和打开目录通过平台端口调用；文件内容读写通过 `internal/platform.FileSystem` 端口执行，默认由 `internal/platform/osfs` 使用 Go 标准库实现。应用服务新增 `Close`，由 GUI 生命周期回调统一释放 ClickHouse 连接池。

### 第三批：平台能力端口

新增 `internal/platform.Platform`，定义保存文件、打开文件和打开配置目录三个能力；同时定义独立的 `FileSystem` 端口，封装文件读取、覆盖写入和创建写入句柄。历史版本的 `internal/platform/wailsadapter` 曾提供 Wails v3 对话框实现；该目录已删除。`internal/platform/osfs` 提供基于 Go 标准库的文件系统实现。根目录 `App` 通过 `NewAppWithPlatform` 注入平台实现，并由 `NewAppWithDependencies` 同时注入文件系统实现。配置导入、配置导出和查询结果导出均通过文件系统端口完成，不再直接调用 `os.ReadFile`、`os.WriteFile` 或 `os.Create`。取消文件对话框仍按原有约定返回空路径，不视为错误。

该平台抽象为历史迁移过程遗留，需在 Gio 平台能力重构中评估保留必要部分或整体删除，不作为必须保留的架构约束。

## Gio 原生 GUI 第一阶段

已新增独立入口 `cmd/meteor-ch-gio`，已删除根目录 Wails 启动方式，新增 `internal/gui/gioapp`，先落地 SQL 工作台主窗口骨架：

- 顶部工具栏：连接、执行 SQL、停止和主题切换入口。
- 左侧连接 / 数据库导航区域，预留连接、数据库、表和系统表层级。
- 中央 SQL 编辑器区域，使用 Gio `widget.Editor` 验证基础文本输入。
- 下方查询结果区域，预留数据表格、统计信息和执行详情。
- 默认深色主题，提供浅色主题切换；默认窗口尺寸 1440 × 900。
- 左侧导航支持显示 / 隐藏；编辑器与结果区比例支持通过分隔条拖动调整，并显示当前比例，仍保留比例边界保护（35%–80%）及按钮式调整入口；左侧导航展开状态和编辑器比例写入 settings.json，启动时恢复。
- Gio 启动时通过共享 `internal/app.Service` 读取本地连接配置，侧栏动态显示连接名称、主机和端口，不展示密码。
- 点击连接配置或工具栏「连接」会异步调用 `TestConnection`，成功后异步加载数据库列表；连接失败、元数据加载失败和空数据库列表均显示对应状态。
- 数据库节点支持展开 / 收起；展开时异步加载该库的表与视图，并展示表引擎、对象数量、空态和错误状态。
- 连接请求使用递增序号丢弃过期响应；数据库元数据加载结果同时校验连接序号和数据库请求序号，避免快速切换连接或重复展开时旧响应覆盖新状态。
- 异步任务完成后通过 Gio `Window.Invalidate` 请求重绘，网络操作不阻塞 UI 事件循环。

该原型已提供比例按钮调整、拖动分隔条、布局状态持久化、真实连接 / 数据库 / 表视图导航，以及 SQL 执行、取消和基础结果表格。结果区展示列名、数据行、耗时、行数、行数上限、截断状态和 SQL 错误；列宽根据列名及前 30 行样本估算，并限制在 10–32 个字符权重，避免所有列固定等宽。数据库树中的表可点击加载表结构，展示字段名、类型、主键标记、默认值标记和字段注释；表结构请求校验连接与请求序号，避免切换连接或快速切换表时旧结果覆盖当前选择。表详情已从左侧导航拆分到可隐藏的右侧面板，选择表后自动展开，支持查看引擎、注释、分区键、排序键、主键和 TTL；完整 DDL 以可纵向滚动的行列表展示，并通过 Gio 剪贴板命令复制原始 DDL。查询结果表格已支持表头与数据行同步横向滚动、拖动表头分隔线调整列宽（80–480dp），并可点击单元格复制值、点击行首操作复制整行（制表符分隔）；Gio 编辑区现已接入多 SQL 标签工作区：启动时恢复 tabs.json 中的标签与活动标签，支持新建、切换、关闭、重命名、拖动排序和保存 SQL 文本，并在窗口退出时保存当前工作区；每个标签现已在当前窗口会话内独立缓存查询结果、最近执行 SQL 和连接 ID；查询执行期间可以切换 / 新建标签，结果返回后按标签 ID 归档，切回时恢复。查询仍为窗口级串行，一次只允许一个查询或导出任务；标签运行态尚未持久化到磁盘；结果区新增 CSV / TSV 导出按钮，通过 `gioui.org/x/explorer` 打开系统保存对话框；导出时重新执行最近一次成功查询的 SQL，通过 `database/sql.Rows` 游标逐行编码并直接写入文件，不再受界面查询行数上限限制。导出针对重新执行时的数据快照，数据变化或非确定性 SQL 可能导致导出内容与此前展示结果不同；导出 SQL 使用最近一次执行时的连接 ID 与 SQL 文本。CSV / TSV 当前支持游标级流式导出，其他格式仍走已加载结果集导出。SQL 标签持久化标题和 SQL 文本；当前支持关闭标签（至少保留一个空白标签）、重命名（拒绝空标题）、拖动排序，并在操作后保存活动标签和顺序。关闭活动标签前会检测 SQL 是否相对已保存快照发生变化，存在未保存修改时要求用户明确确认丢弃；关闭仍在执行查询 / 导出的标签会被阻止，避免丢失任务上下文；标签查询结果和最近执行上下文按标签隔离（仅当前会话内存），尚未持久化。仍未实现 SQL 语法高亮和补全。`widget.Editor` 只是基础文本编辑器，不能视为 Monaco 的等价替代。Gio 依赖固定为 `gioui.org v0.10.3` 与 `gioui.org/x v0.10.3`（文件对话框 Explorer）；需要在具备 Go 1.26 和桌面图形依赖的环境执行 `go mod tidy`、编译和平台验证后，才能确认 API 与依赖完整性。

## 验收原则

每批迁移都必须记录真实测试结果。当前代码通过 GitHub 文件接口提交，但本轮没有可用的本地 Go 执行环境；GitHub 当前 head 也未返回 Actions workflow runs 或 commit status，因此本批不能标记为测试通过。

原生 GUI 原型应以同一台机器、同一构建模式实测冷启动、空闲内存、查询期间内存、安装包压缩体积和大结果集滚动表现。目标值是优化方向，不是框架保证。


### 流式导出统计

Gio 的 CSV / TSV 流式导出使用 `countingWriter` 统计实际写入底层目标的字节数，并记录导出耗时。成功完成时，状态栏展示导出行数、文件大小、耗时和平均行速率；取消或失败时展示已处理行数与已写入字节数。字节统计基于通用 `io.Writer`，不依赖系统文件选择器返回本地文件路径。

统计测试覆盖完整写入与底层部分写入错误。当前仍需在真实桌面环境验证大文件导出耗时、系统文件句柄行为及长时间运行稳定性；本次代码尚未执行本地 Go 测试或构建。

### Gio 收藏 SQL 面板

Gio 顶部工具栏提供「收藏 SQL」入口，使用新架构 `internal/application/savedsql.Service` 和本地 `saved_sql.json` 持久化。支持将当前编辑器 SQL 与当前连接 ID 一起收藏、按名称或 SQL 内容搜索、回填到当前编辑器、重命名收藏和删除单条记录。收藏数据沿用旧版 JSON 文件名与字段结构，迁移时保留既有记录；收藏数量不受查询历史 200 条上限影响，也不会被清空查询历史操作删除。

收藏服务覆盖新增、更新名称、删除、列表和关键字搜索，并保留原记录 ID、SQL、连接 ID 与时间字段；文件写入使用临时文件和替换机制以兼容 Windows。Gio 面板提供异步加载、搜索、回填、重命名和删除；刷新结果通过请求序号隔离，避免较早请求覆盖较新的列表。当前尚未提供在面板内直接编辑 SQL 内容的入口，实际窗口布局与长 SQL 显示仍需 Windows 实机验证。

### Gio 查询历史面板

Gio 顶部工具栏提供查询历史面板，使用新架构 `internal/application/history.Service` 和本地 `history.json`；每条记录展示 SQL 摘要、执行时间、连接 ID、耗时和成功 / 失败状态。支持按 SQL 内容或连接 ID 搜索、回填到当前编辑器、删除单条、清空全部和手动刷新。查询完成后自动写入历史；面板打开时，新增 / 删除 / 清空操作会触发列表刷新。历史记录上限由 `history.MaxEntries` 控制（200 条）。

历史记录列表使用 Gio 虚拟列表；列表读取、删除和清空均在后台执行，结果回到 Gio 主事件循环更新界面。列表刷新采用请求序号隔离，避免快速连续刷新时旧响应覆盖新数据。当前仍需本地验证历史文件损坏、快速连续点击、长 SQL 展示和窄窗口布局；查询历史不提供直接重新执行入口。

### Gio 查询结果视图与内存回收

结果表格的筛选 / 排序视图只保存原始结果行索引，不再为每一行额外保存 `[]any` 切片头；渲染时按索引读取原始查询数据，避免重复持有行切片。排序时仅为当前排序列预计算键，并在筛选条件变化、升降序切换时复用；查询结果流式追加时只为新增行扩展键缓存，切换排序列或切换 / 重置标签结果时才重建缓存。缓存只保留一列的键，避免同时为所有列持有额外副本。新查询启动时同步清空当前标签页缓存的旧列定义和结果行引用，避免 `sqlTabStates` 在活动标签上继续保留上一轮结果。新增 10,000 行结果集的视图构建、筛选和排序键缓存复用基准测试，用于持续观察分配量和构建耗时。

### Gio 查询结果事件队列与取消

查询执行通过批次回调向 Gio 主事件循环发送列定义、结果批次和完成事件。结果事件队列容量限制为 8，每批最多 128 行，最多缓存约 1024 行待消费数据；队列满时生产者等待 GUI 消费，形成背压，而不是预先缓存整次查询结果。每个事件入队后都会请求 Gio 窗口产生下一帧，避免生产者因队列满等待、界面却没有新帧可消费的停滞。取消查询或关闭窗口时会取消执行上下文，使阻塞中的队列写入立即退出；查询代次仍用于丢弃旧查询迟到的事件。

队列背压、取消解除阻塞和队列容量已有单元测试。查询结果本身仍受 10,000 行 UI 展示上限约束；CSV / TSV 导出继续走独立的数据库游标流式路径，不依赖该 UI 结果队列。Windows 实机仍需验证持续大批量查询时的滚动流畅度、内存占用和停止响应。

### Gio SQL 多标签工作区

Gio 编辑区读取并恢复 `TabsManager` 保存的标签快照，支持新建、切换、关闭、重命名和拖动排序；至少保留一个标签，关闭活动标签后自动选择相邻标签，关闭非活动标签不改变当前编辑上下文。标签名称去除首尾空白并拒绝空名称；关闭活动标签前检查 SQL 是否有未保存修改，有修改时要求用户明确确认丢弃；关闭仍有查询或导出任务的标签会被阻止，避免任务结果失去归属。新建、关闭、重命名、排序和切换后都会保存标签文本、标题、顺序与活动标签。

每个标签在当前窗口会话内独立缓存查询结果、最近执行 SQL 和连接 ID；查询期间允许切换 / 新建标签，结果返回后按标签 ID 归档，切回时恢复。查询 / 导出仍为窗口级串行；标签查询运行态和结果尚未持久化到磁盘。标签关闭、未保存修改判断、重命名、排序的纯逻辑已增加单元测试，尚待本地 `gofmt`、Go 测试、编译和桌面拖动交互验收。
### 本轮类型导出处理

流式导出值归一化现在将 `[]byte` 按文本处理，避免被 JSON 编码为 Base64；数组、切片和映射值按 JSON 编码，`time.Time` 继续通过标准 JSON 时间表示输出。新增模拟游标测试覆盖字节切片、数组、映射和时间值。该测试尚未使用真实 ClickHouse 驱动与服务端执行，因此 Decimal、Nullable 包装、时区和驱动版本差异仍需集成验证。

### Gio 表数据浏览分页

### Gio 查询结果列筛选操作符

- 列筛选默认执行大小写无关的包含匹配；前缀 `!` 表示不包含，`=` 表示等于，`!=` 表示不等于。
- 数值比较支持 `>`、`<`、`>=`、`<=`，优先按数值解析；非数值内容再尝试按时间解析，二者均无法解析时不匹配。
- 时间比较支持 `YYYY-MM-DD`、ClickHouse 常见 DateTime / DateTime64 文本（含小数秒）及 RFC3339；带时区的 RFC3339 按显式偏移比较，不带时区的时间文本按 UTC 解释。
- 可用 `>=2026-11-01` 与 `<2026-12-01` 组合出半开时间范围；日期上界采用次日 / 下月边界更容易避免小数秒精度遗漏。
- `is:null` 与 `is:not-null` 可分别筛选空值和非空值；NULL 不参与数值 / 时间比较。
- 多列条件继续按 AND 组合；全局关键字筛选仍独立生效。操作符说明显示在结果表头上方。
- 新增测试覆盖文本操作符、数值边界、NULL 判断、多列组合、DateTime64 小数秒、RFC3339 时区等价和无效时间。


### Gio 查询结果精确数值比较

- 数值排序、列筛选等值比较和大小比较统一使用 `math/big.Rat`，避免将 ClickHouse `UInt64`、`Int64` 或高精度 `Decimal` 转成 `float64` 后发生精度丢失。
- 支持整数、小数和科学计数法数值文本；无法解析为数值时继续按既有时间 / 文本规则处理。
- 新增测试覆盖相邻 UInt64、大于 float64 安全整数范围的值、高精度 Decimal、小数比较和科学计数法。
- 本轮尚未运行本地 gofmt、go test、go vet 或 go build；测试需在本地执行确认。


### Gio 查询结果区间筛选

- 列筛选新增闭区间表达式 `between:下界..上界`，上下界均包含。
- 数值区间使用精确数值比较，保留 UInt64 和 Decimal 的精度；时间区间复用 Date / DateTime / DateTime64 / RFC3339 解析规则，RFC3339 按显式时区比较。
