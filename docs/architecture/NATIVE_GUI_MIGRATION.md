# 原生 GUI 迁移架构说明

## 目标与约束

本次迁移将桌面界面从 Wails WebView 逐步替换为 Gio 原生 GUI，保留 Go 业务逻辑、ClickHouse 驱动和现有本地数据格式。迁移期间旧 Wails + Vue 版本继续作为兼容基线，不提前删除。

- Community 核心采用 MIT 许可证。
- Pro 功能未来通过独立私有仓库和独立构建入口组合，不进入 Community 默认依赖。
- 不使用 Go `plugin` 作为跨平台扩展机制。
- 不以未经实测的框架宣传数据作为启动速度、内存或安装包体积结论。

## 目标分层

```text
Gio GUI / 现有 Wails Adapter
          |
          v
internal/app          GUI 无关的应用用例
          |
          +---- internal/config
          |
          +---- internal/clickhouse
          |
          +---- internal/platform（文件对话框、系统操作）
          |
          +---- internal/edition（后续：Community / Pro 能力接口）
```

## 当前落地

### 第一批：数据库与查询用例

新增 `internal/app.Service`，由应用入口注入配置管理、查询历史、标签页、收藏 SQL、ClickHouse 服务和用户设置依赖。已将以下业务流程从根目录 Wails App 方法委托到该服务：

- 连接保存、删除、测试和断开。
- SQL 查询、查询取消和查询历史记录。
- DDL/DML 单条执行与批量执行。
- 数据库、表、视图、表结构和集群元数据读取。

### 第二批：本地配置与工作区用例

已将以下用例纳入 `internal/app.Service`：

- 连接、文件夹列表及排序；配置导入、导出和格式元信息。
- 查询历史读取、删除和清空；收藏 SQL 增删改查。
- 标签页快照读写；用户设置读取与保存。
- 查询结果导出格式查询，以及向调用方提供的 `io.Writer` 写出结果。

新建连接时应用服务先生成 ID，再持久化并失效对应连接池，避免配置管理器内部生成 ID 后调用方仍持有空 ID 的问题。

默认依赖装配已抽取为 `internal/app.NewDefaultService`，统一创建本地配置管理器、查询历史、标签页、收藏 SQL、用户设置和 ClickHouse 服务；Wails 与 Gio 入口共用该构造函数，避免两套 GUI 各自维护业务依赖。根目录 `App` 仍保留 Wails 公开方法签名，作为旧前端兼容适配层。文件对话框和打开目录通过平台端口调用；文件内容读写通过 `internal/platform.FileSystem` 端口执行，默认由 `internal/platform/osfs` 使用 Go 标准库实现。应用服务新增 `Close`，由 GUI 生命周期回调统一释放 ClickHouse 连接池。

### 第三批：平台能力端口

新增 `internal/platform.Platform`，定义保存文件、打开文件和打开配置目录三个能力；同时定义独立的 `FileSystem` 端口，封装文件读取、覆盖写入和创建写入句柄。`internal/platform/wailsadapter` 提供 Wails v3 对话框实现，`internal/platform/osfs` 提供基于 Go 标准库的文件系统实现。根目录 `App` 通过 `NewAppWithPlatform` 注入平台实现，并由 `NewAppWithDependencies` 同时注入文件系统实现。配置导入、配置导出和查询结果导出均通过文件系统端口完成，不再直接调用 `os.ReadFile`、`os.WriteFile` 或 `os.Create`。取消文件对话框仍按原有约定返回空路径，不视为错误。

该接口让未来 Gio 入口可以注入 Gio 平台实现，而不需要让应用服务依赖 Wails 或 Gio。

## Gio 原生 GUI 第一阶段

已新增独立入口 `cmd/meteor-ch-gio`，不影响根目录 `main.go` 的 Wails 启动方式；新增 `internal/gui/gioapp`，先落地 SQL 工作台主窗口骨架：

- 顶部工具栏：连接、执行 SQL、停止和主题切换入口。
- 左侧连接 / 数据库导航区域，预留连接、数据库、表和系统表层级。
- 中央 SQL 编辑器区域，使用 Gio `widget.Editor` 验证基础文本输入。
- 下方查询结果区域，预留数据表格、统计信息和执行详情。
- 默认深色主题，提供浅色主题切换；默认窗口尺寸 1440 × 900。
- 左侧导航支持显示 / 隐藏；编辑器与结果区比例支持通过分隔条拖动调整，并显示当前比例，仍保留比例边界保护（35%–80%）及按钮式调整入口；左侧导航展开状态和编辑器比例写入 settings.json，启动时恢复。
- Gio 启动时通过共享 `internal/app.Service` 读取本地连接配置，侧栏动态显示连接名称、主机和端口，不展示密码。
- 点击连接配置或工具栏「连接」会异步调用 `TestConnection`，成功后异步加载数据库列表；连接失败、元数据加载失败和空数据库列表均显示对应状态。
- 数据库节点支持展开 / 收起；展开时异步加载该库的表与视图，并展示表引擎、对象数量、空态和错误状态。
- 连接请求使用递增序号丢弃过期响应；数据库元数据加载结果同时校验连接序号和数据库请求序号，避免快速切换连接或重复展开时旧响应覆盖新状态。
- 异步任务完成后通过 Gio `Window.Invalidate` 请求重绘，网络操作不阻塞 UI 事件循环。

该原型已提供比例按钮调整、拖动分隔条、布局状态持久化、真实连接 / 数据库 / 表视图导航，以及 SQL 执行、取消和基础结果表格。结果区展示列名、数据行、耗时、行数、行数上限、截断状态和 SQL 错误；列宽根据列名及前 30 行样本估算，并限制在 10–32 个字符权重，避免所有列固定等宽。数据库树中的表可点击加载表结构，展示字段名、类型、主键标记、默认值标记和字段注释；表结构请求校验连接与请求序号，避免切换连接或快速切换表时旧结果覆盖当前选择。表详情已从左侧导航拆分到可隐藏的右侧面板，选择表后自动展开，支持查看引擎、注释、分区键、排序键、主键和 TTL；完整 DDL 以可纵向滚动的行列表展示，并通过 Gio 剪贴板命令复制原始 DDL。查询结果表格已支持表头与数据行同步横向滚动、拖动表头分隔线调整列宽（80–480dp），并可点击单元格复制值、点击行首操作复制整行（制表符分隔）；Gio 编辑区现已接入多 SQL 标签工作区：启动时恢复 tabs.json 中的标签与活动标签，支持新建、切换、关闭、重命名、拖动排序和保存 SQL 文本，并在窗口退出时保存当前工作区；每个标签现已在当前窗口会话内独立缓存查询结果、最近执行 SQL 和连接 ID；查询执行期间可以切换 / 新建标签，结果返回后按标签 ID 归档，切回时恢复。查询仍为窗口级串行，一次只允许一个查询或导出任务；标签运行态尚未持久化到磁盘；结果区新增 CSV / TSV 导出按钮，通过 `gioui.org/x/explorer` 打开系统保存对话框；导出时重新执行最近一次成功查询的 SQL，通过 `database/sql.Rows` 游标逐行编码并直接写入文件，不再受界面查询行数上限限制。导出针对重新执行时的数据快照，数据变化或非确定性 SQL 可能导致导出内容与此前展示结果不同；导出 SQL 使用最近一次执行时的连接 ID 与 SQL 文本。CSV / TSV 当前支持游标级流式导出，其他格式仍走已加载结果集导出。SQL 标签持久化标题和 SQL 文本；当前支持关闭标签（至少保留一个空白标签）、重命名（拒绝空标题）、拖动排序，并在操作后保存活动标签和顺序。关闭活动标签前会检测 SQL 是否相对已保存快照发生变化，存在未保存修改时要求用户明确确认丢弃；关闭仍在执行查询 / 导出的标签会被阻止，避免丢失任务上下文；标签查询结果和最近执行上下文按标签隔离（仅当前会话内存），尚未持久化。仍未实现 SQL 语法高亮和补全。`widget.Editor` 只是基础文本编辑器，不能视为 Monaco 的等价替代。Gio 依赖固定为 `gioui.org v0.10.3` 与 `gioui.org/x v0.10.3`（文件对话框 Explorer）；需要在具备 Go 1.26 和桌面图形依赖的环境执行 `go mod tidy`、编译和平台验证后，才能确认 API 与依赖完整性。

## 验收原则

每批迁移都必须记录真实测试结果。当前代码通过 GitHub 文件接口提交，但本轮没有可用的本地 Go 执行环境；GitHub 当前 head 也未返回 Actions workflow runs 或 commit status，因此本批不能标记为测试通过。

原生 GUI 原型应以同一台机器、同一构建模式实测冷启动、空闲内存、查询期间内存、安装包压缩体积和大结果集滚动表现。目标值是优化方向，不是框架保证。


### 流式导出统计

Gio 的 CSV / TSV 流式导出使用 `countingWriter` 统计实际写入底层目标的字节数，并记录导出耗时。成功完成时，状态栏展示导出行数、文件大小、耗时和平均行速率；取消或失败时展示已处理行数与已写入字节数。字节统计基于通用 `io.Writer`，不依赖系统文件选择器返回本地文件路径。

统计测试覆盖完整写入与底层部分写入错误。当前仍需在真实桌面环境验证大文件导出耗时、系统文件句柄行为及长时间运行稳定性；本次代码尚未执行本地 Go 测试或构建。

### Gio SQL 多标签工作区

Gio 编辑区读取并恢复 `TabsManager` 保存的标签快照，支持新建、切换、关闭、重命名和拖动排序；至少保留一个标签，关闭活动标签后自动选择相邻标签，关闭非活动标签不改变当前编辑上下文。标签名称去除首尾空白并拒绝空名称；关闭仍有查询或导出任务的标签会被阻止，避免任务结果失去归属。新建、关闭、重命名、排序和切换后都会保存标签文本、标题、顺序与活动标签。

每个标签在当前窗口会话内独立缓存查询结果、最近执行 SQL 和连接 ID；查询期间允许切换 / 新建标签，结果返回后按标签 ID 归档，切回时恢复。查询 / 导出仍为窗口级串行；标签查询运行态和结果尚未持久化到磁盘。标签关闭、未保存修改判断、重命名、排序的纯逻辑已增加单元测试，尚待本地 `gofmt`、Go 测试、编译和桌面拖动交互验收。
### 本轮类型导出处理

流式导出值归一化现在将 `[]byte` 按文本处理，避免被 JSON 编码为 Base64；数组、切片和映射值按 JSON 编码，`time.Time` 继续通过标准 JSON 时间表示输出。新增模拟游标测试覆盖字节切片、数组、映射和时间值。该测试尚未使用真实 ClickHouse 驱动与服务端执行，因此 Decimal、Nullable 包装、时区和驱动版本差异仍需集成验证。
